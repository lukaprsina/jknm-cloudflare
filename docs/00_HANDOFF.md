## Decisions already made

- Vercel/Next.js → Cloudflare/Vinext (Workers Paid). **Workers Paid was bought 2026-11-01** (05: `limits.cpuMs: 60000` accepted and enforced; the 04 Free-plan numbers are superseded). Reason: hit Vercel's 4h Fluid CPU limit. Vercel Pro (€20) is bought for the duration of the refactor, so the site is no longer throttled.
- B2 → R2. Images go through Cloudflare Images (the `IMAGES` binding is already in `cloudflare.config.ts`). The old image pipeline is broken and gets dropped.
- Supabase + Drizzle stay, via Hyperdrive. No D1 (SQLite, transactions). (research) Drizzle's D1 `transaction()` sends raw `begin`/`commit` and D1 only documents `batch()` as transactional; `publish` would need a rewrite. Revisit only if a read-heavy, batch-only design is wanted.
- (research) Driver is `pg` with `drizzle-orm/node-postgres`, not postgres-js (unsupported over Hyperdrive). `db` must be request-scoped (no module-level pool); keep `import { db }` as an AsyncLocalStorage-backed proxy typed as `PgDatabase` so pglite tests still work.
- (research) Create the Hyperdrive config with **query caching disabled**: it is on by default (60 s) and writes never invalidate it, which would break `updateTag` and session reads. `DATABASE_URL` in `.env.local` is the Supabase transaction pooler (6543). Spike: the direct host is unreachable from an IPv4-only machine; the session pooler (5432) works. **Deployed check (03, appendix): point Hyperdrive at the Supabase direct host `db.<ref>.supabase.co:5432`.** It is reachable from Hyperdrive (40/40 requests at concurrency 20, transactions and `FOR UPDATE` correct). The session pooler (5432) failed about half of a 20-way parallel load with `EMAXCONNSESSION` (Supabase pool_size 15, Hyperdrive default connection limit 20); if it is used, set `origin_connection_limit` <= 15. Hyperdrive caching was confirmed to serve stale reads after `revalidateTag` when enabled, so keep it disabled. `cf hyperdrive create` has no caching flag; use `cf hyperdrive update <id> --caching-disabled`. (07) Never use a session-level `SET` on a connection to the Supabase transaction pooler: it leaks to the next client (a `SET default_transaction_read_only` made prod connections read-only for minutes); use `BEGIN READ ONLY`. Never `end()` the pool/client when `fetch` returns: production RSC streams Suspense content afterwards ("Cannot use a pool after calling end"). `drizzle-kit` uses a direct `DATABASE_URL`.
- Algolia → zbsearch (Orama fork, has Slovenian stemming), client-side local artifact (see REPLACE table).
- EditorJS stays. TipTap migration is parked.
- Tooling: `vp` (Vite+, pnpm) and the `cf` CLI. `cf cli search "<task>"` is the discovery entry point; don't walk `--help` trees.
- oRPC is dropped in favour of plain Server Actions (Vinext reportedly handles either, so this is a design choice, not a constraint).
- `@t3-oss/env-core` (or similar) for env, reading the `cloudflare:workers` env. (research) `process.env` is populated at our compat date, but only from bindings declared in `cloudflare.config.ts` (text, json, secret); undeclared `.env.local` keys never reach the Worker. `NEXT_PUBLIC_*` is inlined at build time, so it must exist in CI. Local Hyperdrive needs `CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_<BINDING>` (works from a dotenv file; `vp dev` and `vp test` throw without it; spike fixed `vp test` by skipping the vinext/Cloudflare plugins under vitest and excluding `.references` in `vite.config.ts`). Verified in dev and the production preview: declared bindings populate `process.env`, undeclared `.env.local` keys do not, and `env` from `cloudflare:workers` works at module scope.
- Member sync stays: new users added to the Google directory must be synced in as authors. Replace `googleapis`/`google-auth-library` with `fetch` + `jose`. (07) Verified: same 101 users and digest as the old code in Node, local workerd and a deployed Worker; 3-6 ms CPU per sync. The old code does not impersonate (no `sub`; a made-up one gives `invalid_grant`). Env PEMs with literal `\n` must be converted before `importPKCS8`.
- shadcn/ui on Base UI (`base-nova`; the old site is Radix, `default` style). Add components on demand with `shadcn add`, one commit per add so the pristine output stays diffable. `docs/shadcn-customizations.md` lists the six old components that were modified (`breadcrumb`, `carousel`, `command`, `navigation-menu`, `sheet`, `table`); re-apply those by hand if still wanted. Our own (non-ui) components get cleaned and redesigned, so don't just copy them.

## KEEP (port, improve while porting)

- Domain model and rules: `server/article/*` (`lifecycle-rules`, `reconcile-media`, `new-article`, `lifecycle`, `slug`, `get-article`, `article-queries`), the `articles` status-enum schema, `server/db/schema.ts`, `server/author/*`. These are already framework-agnostic; keep them and their pglite-based tests.
- `lib/cache-policy.ts` (pure event → invalidations mapping with a reachability test). It is a deep module. Only the adapters beneath it change, depending on what the Vinext cache preserves.
- better-auth (Google, `@jknm.si` gate, `sign-in-gate`, `session-shape`). (research) The `account.issuer` migration is obsolete: better-auth 1.7.3+ dropped the requirement, and the old schema's `issuer NOT NULL` plus the unique index `account_issuer_account_id_uidx` would block sign-in. Remove it from the schema; if production has the column, relax it and drop the index. Do not port `backfill-account-issuer.ts`. (07) Build one `betterAuth()` per isolate over the ALS db proxy (works under pglite, `vp dev`, and `vp build`+preview; per-request also works but isn't needed). **Production `account` has `issuer NOT NULL` and the unique index `account_issuer_account_id_uidx`: run `ALTER COLUMN issuer DROP NOT NULL` before the new site takes sign-ins; drop the index/column only after the old Vercel site is gone (it still writes `issuer`).** Duplicate check is clean. Set `advanced.useSecureCookies` explicitly (not `Secure` by default on Workers: `NODE_ENV` is unset). `waitUntil` (from `cloudflare:workers`) is not wired in `create_auth`; add the option when something needs it. Calls to `auth.api.*` outside a request (Cron/Queue) throw 500 unless `baseURL.fallback` is set. Keep the Drizzle schema in one module: splitting tables across files caused a production-only chunk cycle ("Class extends value undefined"), invisible in `vp dev`; run build+preview early after adding better-auth.
- Legacy redirects: `app/si/route.ts`, `app/si/[...path]/route.ts`, `lib/legacy-si-paths.ts`, `resolve-legacy-article-link` (old 2008 URLs still need 308/410 for SEO).
- `/novica/<slug>` response contract (see "`/novica/<slug>` response contract" in old `architecture.md`).
- `media_to_articles` reconciliation, content-addressed (sha256) media, `gradivo.jknm.org` as the media origin. Existing `content_json` has those URLs baked in, so copy the bucket to R2 and repoint the custom domain; no content rewrite.
- **`scripts/sweep-stale-content.ts` is not a migration script.** It clears orphaned media (48h) and `deleted` articles past their grace window. Port it as a Cron Trigger.
- `scripts/backup-db.ps1`-style backups, if still wanted.
- Contact form + Resend (optional: `cf email-sending` exists now).
- Tailwind v4, EditorJS tools and patch (`patches/@editorjs%2Feditorjs@2.31.6.patch`), `nuqs`, `react-hook-form` + zod, `lucide-react`, `motion`, `cmdk` and similar UI deps, as needed.
- (research) The pnpm override for `zbsearch: 4.0.0` is obsolete: the `workspace:*` publish bug is fixed in 4.0.1. 4.0.1 also changed tokenization, so re-run the #45 size and hit-count numbers on the version we install.

## Risks / things to verify first

(research, tested in 03) Server Action error redaction, `updateTag` read-your-writes, Date-as-string on cache hits and the `pg` + AsyncLocalStorage `db` proxy (also pglite-compatible) all passed locally. **`revalidateTag` imported from `next/cache` in a `scheduled` handler silently does nothing**; route it through the vinext handler to an internal route (local trigger: `/cdn-cgi/local/scheduled`). One-argument `revalidateTag` is a TS error; use `updateTag` in actions or `revalidateTag(tag, "max")`. Hyperdrive pooling is resolved (see decisions). (06, deployed) `fetch`+`scheduled`+`queue` compose with the vinext handler and Response Store, and reach the db proxy. `revalidateTag` from `next/cache` in `queue`/`scheduled` is a no-op deployed; route through `handler.fetch` to an internal Route Handler (works, purges a cached read), and **guard that route in the entry** since it is internet-reachable. `updateTag` and `revalidateTag(tag, {expire:0})` give read-your-writes; **`revalidateTag(tag, "max")` on a cached ISR page stays stale until the page's own TTL (still stale at 56 s), so use hard expiry for anything feeding the homepage**. Multi-colo behaviour unverified (all requests hit one colo). `NEXT_PUBLIC_*` literals are inlined at build (including from `.env.local`); computed-key lookups are not, and the variables must exist in CI. Full dependency set: Worker ~3.0 MiB raw / 861 KiB gzip, startup 15-30 ms, cold request ~0.7 s vs 0.22 s warm, so the bundle-size risk is dropped. EditorJS works under `vp dev` and build+preview, but `ssr:false` still puts its 313 KB chunk in the SSR bundle; nuqs needs `NuqsAdapter` from `nuqs/adapters/next/app` or SSR throws.

(research) Ranked by likelihood of forcing a design change: Hyperdrive caching default; better-auth schema mismatch; Supabase direct vs pooler connectivity; the request-scoped db/auth seam; search build memory (128 MB); cron needs a custom worker entry re-exporting vinext's handler; beta toolchain churn. Server Actions are supported and thrown errors **are** redacted in production (digest, React error #441), so keep the `Result` type. `updateTag` works only inside actions; `unstable_cache` still JSON-serialises, so `revive-cache-dates` stays; `"use cache"` needs the incomplete `cacheComponents`, so stay on `unstable_cache`.

1. **Vinext + Server Actions + cache invalidation.** The old design used Next's `updateTag` inside real Server Actions. Smoke-test one action, one invalidation, and the Hyperdrive Postgres connection before porting any UI. Old ADRs 0005 and 0006 (`.references/jknm/docs/adr/`) explain the caching constraints.
2. ~~Workers limits~~ Resolved (05, 06): bundle and search-build CPU fit on Paid.
3. **Server Action error redaction** in Vinext production builds, which decides whether the `Result` wrapper is needed.
4. Old `docs/architecture.md` is stale (it still describes Vercel and better-auth 1.6.27); trust `package.json` and the code.
